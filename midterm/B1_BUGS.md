## วิธีกรอก (อ่านก่อนเริ่ม)

กรอกให้ครบ **ทั้ง 6 บั๊ก** · แต่ละบั๊กเขียน 3 อย่างด้วย **คำของตัวเอง** (จะถูกสุ่มถามใน oral)

| คอลัมน์ | ใส่อะไร | ตัวอย่างสิ่งที่เขียน *(บั๊กสมมติ)* |
|---|---|---|
| **ไฟล์ : บรรทัด** | ไฟล์ที่แก้ + เลขบรรทัด | `Foo.jsx : 12` |
| **สาเหตุ** | **ทำไม** มันทำงานผิด (ไม่ใช่แค่ "พิมพ์ผิด") | "ใส่วงเล็บท้ายชื่อฟังก์ชัน เลยถูกเรียกทันทีตอน render" |

## บันทึกของฉัน — กรอกทั้ง 6 บั๊ก

| # | อาการ (ให้มาแล้ว) | ไฟล์ : บรรทัด | สาเหตุ (ทำไมผิด) | แก้อย่างไร |
|---|---|---|---|---|
| 1 | Console เตือนสีเหลืองเรื่องรายการ (list) ที่แผงสรุป | บรรทัดที่ 12 | .map() สร้าง element หลายตัวแต่ไม่ได้ใส่ prop key ให้แต่ละตัว  React ต้องการ key ที่ไม่ซ้ำเพื่อรู้ว่า element ไหนคือของเดิมตอนที่จะ re-render | เพิ่ม key={key} เข้าไปที่ article เพราะ key เป็นตัวแปรแรกที่ destructure มาจาก item อยู่แล้ว |
| 2 | ตัวเลข "เสร็จสิ้น" ในแผงสรุปไม่ตรงกับที่เห็นจริง | บรรทัดที่ 50 | บรรทัด completed เอา .filter() ไปเทียบกับ in-progress แทนที่จะเทียบกับ completed | ปลี่ยนเงื่อนไขใน .filter() จาก request.status  in-progress เป็น request.status  completed |
| 3 | กดตัวกรองสถานะใด ๆ แล้วผลไม่เปลี่ยน (เหมือนกรองไม่ทำงาน) | บรรทัดที่ 53 | ในบรรทัด filteredRequests	โค้ด hardcode filter ไว้ที่ 'pending' ตายตัว ไม่ว่า statusFilter จะเป็นค่าอะไรก็ไม่ถูกนำมาเทียบจริง | เปลี่ยนเงื่อนไขให้เทียบกับตัวแปร statusFilter ที่รับมาจาก state แทนการ hardcode pending |
| 4 | เปลี่ยน URL `REQ-101` → `REQ-102` แล้วข้อมูลไม่เปลี่ยน | บรรทัดที่ 28 | useEffect มี dependency array ว่างเปล่า ทำให้ effect รันแค่ครั้งเดียวตอน mount ไม่รู้ว่า URL param เปลี่ยนแล้วต้อง fetch ข้อมูลใหม่ | เพิ่ม requestId เข้าไปใน dependency array เป็น requestId เพื่อให้ effect รันใหม่ทุกครั้งที่ URL param เปลี่ยน |
| 5 | กด "ลบ" แล้วการ์ดหาย แต่ตัวเลขในแผงสรุปไม่ลด | บรรทัดที่ 51 | useMemo มี dependency array ว่างเปล่า ทำให้ summary ถูกคำนวณแค่ครั้งเดียวตอน mount แล้วค้างค่าเดิมตลอด ไม่ re-calculate เมื่อ requests เปลี่ยน | เพิ่ม requests เข้าไปใน dependency array เป็น [requests] เพื่อให้คำนวณใหม่ทุกครั้งที่ข้อมูลเปลี่ยน |
| 6 | กด "ลบ" แล้วหน้าพัง/ว่างเปล่า | บรรทัดที่ 68 | เรียก deleteRequest(requestId) โดยไม่ใส่ await ทั้งที่ฟังก์ชันนี้เป็น async คืนค่าเป็น Promise —พอเอา Promise ไปใส่ setRequests() ตรง ๆ แล้ว component อื่นเอา requests ไปเรียก .filter() ต่อจะพังเพราะไม่ใช่ array จริง | ใส่ await หน้า deleteRequest(requestId) เพื่อรอให้ Promise resolve ก่อนแล้วค่อยได้ array จริงมา |
